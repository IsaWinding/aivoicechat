# 语音聊天测试与体验对比

测试日期：2026-09-08。项目模型：Cursor `composer-2.5`，SDK 1.0.6。

## 最新更新：独立口语组织

后续优化已将“选取开头正文”替换为独立口语模型调用。下文保留上一阶段的对比记录，涉及摘要生成的旧描述以本节为准。

本轮输入包含最新问题、最近八条用户/助手消息、当前完整结果、重要异常和最近六次口语记录；输出仅为口语正文。默认目标 60–160 字，上限 220 字。完整文字回答不变，口语版本另外显示。异常长结果超过 120,000 字符时保留首尾并明确标注省略，不能保证涵盖被省略部分；近期消息和异常也有长度上限。

口语 Agent 使用相同 Cursor 模型，禁用工具和环境设置来源；与执行任务的会话分离。关闭播报不调用口语模型。插话、停止、会话清理及关闭播报使旧口语失效；超时 15 秒或输出不合要求时明确提示查看文字，不回退到机械截断。记录的播放状态并非逐字听取确认。

26 项本地自动化测试、构建和类型检查通过。新增真实模型测试 `npm run test:spoken` 的三项结果如下（单次样例，耗时仅为新增口语整理阶段，不代表声音播放延迟）：

| 场景 | 额外生成耗时 | 实际结果 |
| --- | ---: | --- |
| 60 条进度后出现登录失败结论 | 9,604 ms | 首句“还不能上线”，指出弱网登录超时和验证未通过 |
| 已讲结论后追问“为什么” | 3,704 ms | 解释弱网超时原因，没有重新逐项播报进度 |
| 部分修改完成但保存失败 | 3,075 ms | 明确“还没有全部完成”，保留保存失败和验证未执行 |

本轮未重做真实麦克风、音色或外放回声测试。开启语音每轮额外使用一次模型调用，相应增加等待与费用；现有 VSIX 未重新打包。

## 结论与测试边界

完成真实 Cursor 模型对话测试、本地 HTTP 桥测试、页面交互检查和模拟语音事件回归测试。构建、类型检查、17 项本地测试、真实模型冒烟测试和两轮五场景对话测试通过。

这不是与 GPT-6 语音的双端录音 A/B 测试。官方 GPT-6 Astra 模型页标明音频不受支持；这里以 OpenAI Realtime 的语音打断、断句与上下文处理机制作为功能参照。未调用 OpenAI 语音 API，未替换项目模型。

内置浏览器尝试启动识别后，页面报告语音服务网络连接失败。因此尚未验证真实麦克风识别准确率、外放回声、音色、口头插话到声音停止的延迟。

## 修复并回归验证的问题

- 关闭识别后，结束回调重新启动自动发送计时器，导致未确认的话被发出。
- 识别服务报错后仍发送不完整的句子。
- 请求失败时清空已识别文字。现在保留内容并提供显式重试；同一消息重试使用同一标识，由本地桥去重。
- 关闭播报时，已排队的延迟播放仍可能开始。现在使旧播放回调失效。
- 第一段补充等待旧任务取消期间，用户再次开口，旧任务结束却抢先处理第一段。现在等待最新一段确认，再合并补充。
- 标题可能被当作摘要，后文验证失败信息可能遗漏。现在跳过标题，保留后文失败或未验证说明，限制播报长度，并过滤代码、命令及链接地址。
- 麦克风错误提示被普通“已停止”状态覆盖。现在保留识别错误说明。

## 最近一次真实模型测试

每个场景一次，不是延迟分位数或稳定性基准。时间从调用 AgentSession.send 开始计算；不含麦克风识别、1.2 秒停顿等待、初次创建 Agent 和语音合成启动。

| 场景 | 首次文字 | 本轮结束 | 验证结果 |
| --- | ---: | ---: | --- |
| 摘要＋代码示例＋测试命令 | 7,437 ms | 7,713 ms | 播报不含示例代码或 npm test；保留未真机验证说明 |
| 记住红色偏好 | 2,786 ms | 3,057 ms | 正确确认红色 |
| 最新纠正为蓝色 | 1,979 ms | 2,217 ms | 以蓝色为最终要求 |
| 长回答出现文字后立即取消 | 3,898 ms | 3,901 ms | SDK 返回 cancelled；取消确认与结束约 3 ms |
| 取消后继续追问颜色 | 2,136 ms | 2,421 ms | 保留上下文，回答蓝色 |

前一轮取消约 4 ms。这里测的是 SDK 取消生成，不是声音停止；不能用 3–4 ms 宣称真实语音打断延迟。

模型仍可能使用“已改好”等执行式表述来确认虚构偏好。当前测试证明最新偏好被保留，不代表所有回答措辞已经达到自然语音助手标准。

## 与官方实时语音机制的对比

| 体验点 | 官方参照 | 当前项目与差距 |
| --- | --- | --- |
| 开口打断 | VAD 检测说话并取消生成 | 接收浏览器 speechstart／识别片段后停止播放并取消旧任务；控制流程测试通过，真实声学延迟未测 |
| 判断是否说完 | semantic VAD 按语义判断说话完成概率 | 当前仍是固定 1.2 秒停顿，新的语音片段重置等待；长思考停顿仍可能误判 |
| 回答挑重点 | 可通过提示控制语音回应风格 | 模型先写结论，客户端选择开头正文并保留风险句；是规则选取，不是独立语义摘要模型 |
| 打断后的上下文 | 可截断未听到的上一条音频内容 | SDK 会话能保留最新纠正；尚未按实际播放位置同步“你听到了哪里” |
| 响应速度 | 实时音频交互链路 | 识别→文字模型→完整回答→TTS，存在串行等待；本次文本首段约 2.0–7.4 秒 |
| 自然音色／回声 | 取决于音频模型及客户端音频处理 | 仍使用系统／浏览器 TTS；建议耳机，未验证可靠的外放回声消除 |

## 复测方式

- `npm run compile`：扩展构建。
- `npx tsc --noEmit`：类型检查。
- `npm test`：17 项本地测试，含模拟语音与真实本地 HTTP 桥。
- `npm run test:smoke`：真实 Agent 只读冒烟测试。
- `npm run test:live`：五场景真实模型对话测试，输出到 `out/live-conversation-results.json`。

真实模型测试需在进程环境提供 CURSOR_API_KEY。测试代码与报告不保存密钥。测试预览不会执行 Agent 任务；已有 0.5.1 VSIX 未重新打包。
